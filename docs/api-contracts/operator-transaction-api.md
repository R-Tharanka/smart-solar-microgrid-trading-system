# Operator Transaction API Contract

Base path: `/api`  
Authentication: Bearer token for protected endpoints  
Owner: Member 4

## QR Security Decision

The QR code must not contain only a reservation id. It should contain an opaque transaction token generated by the API. The API stores only a hash of the token, along with expiry and reservation state.

Recommended QR payload:

```json
{
  "reservationCode": "RSV-20260923-0001",
  "transactionToken": "opaque-random-token",
  "expiresAtUtc": "2026-09-24T04:30:00Z"
}
```

Rules:

- Token is generated server-side.
- Token hash is stored in `energyReservations.qrTokenHash`.
- QR expires at or before the scheduled reservation window.
- Only `Approved` reservations can receive QR data.
- Verified and completed reservations cannot be verified/finalized again.

## Endpoints

### Issue QR Transaction

`POST /api/reservations/{reservationId}/qr`

Authorization: Owning Prosumer or Backoffice

Related collection: `energyReservations`

Validation:

- Reservation must exist.
- Reservation must be `Approved`.
- Authenticated Prosumer must own the reservation if called from Android.
- Existing non-expired QR may be reused or rotated based on implementation decision.

Success: `200 OK`

```json
{
  "success": true,
  "message": "QR transaction issued.",
  "data": {
    "reservationCode": "RSV-20260923-0001",
    "qrPayload": "{...}",
    "expiresAtUtc": "2026-09-24T04:30:00Z"
  }
}
```

Errors: `400`, `401`, `403`, `404`, `409`

### Verify QR Transaction

`POST /api/transactions/verify`

Authorization: GridOperator

Related collection: `energyReservations`

Request:

```json
{
  "reservationCode": "RSV-20260923-0001",
  "transactionToken": "opaque-random-token"
}
```

Validation:

- Authenticated user must be a Grid Operator.
- Reservation must exist.
- QR token hash must match.
- QR must not be expired.
- Reservation must be in `QrIssued` state.
- Reservation must not be cancelled, rejected, completed or expired.

Success: `200 OK`

```json
{
  "success": true,
  "message": "Transaction verified.",
  "data": {
    "reservationId": "66f300000000000000000001",
    "reservationCode": "RSV-20260923-0001",
    "prosumerNic": "200012345678",
    "stationId": "66f100000000000000000001",
    "requestedEnergyKwh": 10.0,
    "status": "Verified"
  }
}
```

Errors: `400`, `401`, `403`, `404`, `409`

### Finalize Energy Transfer

`POST /api/transactions/finalize`

Authorization: GridOperator

Related collections: `energyReservations`, `energyBookingSlots`

Request:

```json
{
  "reservationCode": "RSV-20260923-0001",
  "confirmationNote": "Energy transfer completed",
  "actualEnergyTransferredKwh": 9.8
}
```

`actualEnergyTransferredKwh` is optional for backward compatibility. When omitted, the API records the full reserved `requestedEnergyKwh`. When supplied, it must be greater than zero and cannot exceed the reserved amount.

Validation:

- Authenticated user must be a Grid Operator.
- Reservation must be `Verified`.
- Reservation must not already be `Completed`.
- Reservation completion and closure of its reserved booking slot are committed in one MongoDB transaction.
- The consumed booking slot becomes `Expired`; a failed slot transition rolls back reservation completion.

Success: `200 OK`

```json
{
  "success": true,
  "message": "Energy transfer finalized.",
  "data": {
    "reservationCode": "RSV-20260923-0001",
    "status": "Completed",
    "actualEnergyTransferredKwh": 9.8,
    "finalizedAtUtc": "2026-09-24T05:30:00Z"
  }
}
```

Errors: `400`, `401`, `403`, `404`, `409`

### Get Transaction Details

`GET /api/transactions/{reservationCode}`

Authorization: GridOperator or Backoffice

Related collection: `energyReservations`

Use:

- Operator confirmation screen.
- Web operational transaction view.

Success: `200 OK`

Errors: `401`, `403`, `404`
